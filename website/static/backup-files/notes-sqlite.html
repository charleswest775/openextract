What it holds

Before iOS 9, the Notes app kept notes here. Each note is a row in ZNOTE, and its text is HTML in ZNOTEBODY.ZCONTENT.

iOS 9 moved notes to NoteStore.sqlite, but the old file stayed: every backup we checked, up to iOS 17.3, still has it.

Key columns

  • ZNOTE.ZTITLE: The note's title.
  • ZNOTE.ZCREATIONDATE: When it was created.
  • ZNOTE.ZMODIFICATIONDATE: When it was last changed.
  • ZNOTEBODY.ZOWNER: Which note the body belongs to: its Z_PK in ZNOTE.
  • ZNOTEBODY.ZCONTENT: The note's text, as HTML.

Tables by iOS version

The same 14 tables in every backup we opened (iOS 13.3.1, 13.4.1, 15.3.1, 16.1.2 and 17.3):

ACHANGE, ATRANSACTION, ATRANSACTIONSTRING, ZACCOUNT, ZNEXTID, ZNOTE, ZNOTEATTACHMENT, ZNOTEBODY, ZNOTECHANGE, ZPROPERTY, ZSTORE, Z_METADATA, Z_MODELCACHE, Z_PRIMARYKEY

The iOS 16.0 backup is encrypted with a password that isn't public, so only its list of files was checked, not its tables.

How to open it

Free, in OpenExtract. Open the backup in OpenExtract and choose Notes. OpenExtract looks here first and shows these notes if there are any; otherwise it reads NoteStore.sqlite. Step by step: Export notes from an iPhone backup.

By hand. In a backup that isn't encrypted, ca/ca3bc056d4da0bbf88b5fb3be254f3b7147e639c is an ordinary SQLite database with no extension. Copy it out of the backup folder and open the copy with any SQLite browser, such as DB Browser for SQLite. Work on a copy: changing anything inside a backup can stop it from restoring.

In an encrypted backup, the file in the backup folder is encrypted with a key of its own, which only the backup password unlocks, so nothing can open it until it's decrypted. OpenExtract does that when you open the backup and type its password.
