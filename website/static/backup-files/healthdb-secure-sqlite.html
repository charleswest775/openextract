What it holds

healthdb_secure.sqlite holds the Health app's records. Each sample is a row in samples, with its type and its start and end times. The value of a measurement, such as a step count or a heart rate, is in quantity_samples, matched by data_id.

Health/healthdb.sqlite (fa2e5ac3b7a62c8b7cb21e440c79eedd218550ea): The Health database's other file. It doesn't hold the samples; its tables list the apps and devices the data came from (sources, source_devices) and which apps may use Health data (authorization). We saw it next to healthdb_secure.sqlite in iOS 13.3.1, 13.4.1, 15.3.1, 16.0, 16.1.2 and 17.3.

Key columns

  • samples.data_id: The sample's id, shared with its row in quantity_samples.
  • samples.start_date: When the sample starts.
  • samples.end_date: When it ends.
  • samples.data_type: What kind of sample it is, as a number.
  • quantity_samples.data_id: The sample's id in samples.
  • quantity_samples.quantity: The measured value.

How to open it

OpenExtract doesn't read it yet. OpenExtract doesn't have a Health screen yet.

Always encrypted on disk. This file is only in encrypted backups, so the copy in the backup folder is encrypted with a key of its own, which only the backup password unlocks. Nothing can open it until it's decrypted. Tools such as iphone_backup_decrypt, the open-source library OpenExtract uses, can decrypt a single file; then open the decrypted copy with any SQLite browser, such as DB Browser for SQLite.
