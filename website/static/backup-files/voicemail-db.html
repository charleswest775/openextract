What it holds

voicemail.db lists the voicemails the Phone app has downloaded. Each row in the voicemail table has the caller's number, the date and the length.

The audio isn't in the database. Each voicemail is its own file, Library/Voicemail/<ROWID>.amr in HomeDomain, named after its row in the table. The transcript the Phone app shows is in a file of its own next to the recording, not in voicemail.db.

Newer iPhones can also keep voicemails in a separate store for each phone line, in a folder under Library/Voicemail/ whose name starts with A-. The iOS 16.1.2 and 17.3 backups we checked have such a folder.

Only Visual Voicemail is here. Voicemail kept only on the carrier's system, the kind you dial in to hear, isn't in a backup. A voicemail deleted on the phone stays in the table while it's in the Phone app's Deleted Messages list.

Key columns

  • voicemail.sender: The caller's number.
  • voicemail.date: When it was left, in seconds since 1 January 1970 (Unix time).
  • voicemail.duration: Length in seconds.
  • voicemail.flags: Bit flags, such as whether it has been played.
  • voicemail.trashed_date: When it was deleted on the phone; 0 or empty if it wasn't.

Tables by iOS version

iOS 13.3.1 has 2 tables:

_SqliteDatabaseProperties, voicemail

Then, version by version:

  • iOS 13.4.1 (2 tables): the same as iOS 13.3.1.
  • iOS 15.3.1 (4 tables): adds deleted, map.
  • iOS 16.1.2 (4 tables): the same as iOS 15.3.1.
  • iOS 17.3 (4 tables): the same as iOS 16.1.2.

The iOS 16.0 backup is encrypted with a password that isn't public, so only its list of files was checked, not its tables.

How to open it

Free, in OpenExtract. Open the backup in OpenExtract and choose Voicemail. Timeline uses it too. OpenExtract reads voicemail.db and the per-line stores, plays each voicemail, shows its transcript if the iPhone made one, lists spam and deleted ones under Spam and Deleted, and saves the audio with a CSV list. Step by step: Save voicemails from an iPhone backup.

By hand. In a backup that isn't encrypted, 99/992df473bbb9e132f4b3b6e4d33f72171e97bc7a is an ordinary SQLite database with no extension. Copy it out of the backup folder and open the copy with any SQLite browser, such as DB Browser for SQLite. Work on a copy: changing anything inside a backup can stop it from restoring.

In an encrypted backup, the file in the backup folder is encrypted with a key of its own, which only the backup password unlocks, so nothing can open it until it's decrypted. OpenExtract does that when you open the backup and type its password.
