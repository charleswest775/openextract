What it holds

places.db is where current Firefox for iOS versions keep history. Its tables are named like desktop Firefox's: moz_places has one row per web address and moz_historyvisits one row per visit.

One difference from desktop Firefox: visit_date here is in milliseconds, not microseconds.

Key columns

  • moz_places.url: The web address.
  • moz_places.title: The page's title.
  • moz_historyvisits.place_id: Which address was visited: its id in moz_places.
  • moz_historyvisits.visit_date: When, in milliseconds since 1 January 1970 (UTC).

Tables by iOS version

The same 18 tables in every backup we opened (iOS 15.3.1, 16.1.2 and 17.3):

moz_bookmarks, moz_bookmarks_deleted, moz_bookmarks_synced, moz_bookmarks_synced_structure, moz_bookmarks_synced_tag_relation, moz_historyvisit_tombstones, moz_historyvisits, moz_inputhistory, moz_keywords, moz_meta, moz_origins, moz_places, moz_places_metadata, moz_places_metadata_search_queries, moz_places_stale_frecencies, moz_places_tombstones, moz_tags, moz_tags_relation

How to open it

Free, in OpenExtract. Open the backup in OpenExtract and choose Web history. Timeline uses it too. OpenExtract reads both Firefox files and lists their visits with Safari's. Step by step: Export Safari and Firefox history.

By hand. In a backup that isn't encrypted, ab/ab87b1b6904c441f3814d12748a1a32750a43496 is an ordinary SQLite database with no extension. Copy it out of the backup folder and open the copy with any SQLite browser, such as DB Browser for SQLite. Work on a copy: changing anything inside a backup can stop it from restoring.

In an encrypted backup, the file in the backup folder is encrypted with a key of its own, which only the backup password unlocks, so nothing can open it until it's decrypted. OpenExtract does that when you open the backup and type its password.
