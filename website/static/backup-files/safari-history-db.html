What it holds

History.db is Safari's history. history_items has one row per web address, with how many times it was visited. history_visits has one row per visit, with its time and the page's title.

Key columns

  • history_items.url: The web address.
  • history_items.visit_count: How many times it was visited.
  • history_visits.history_item: Which address was visited: its id in history_items.
  • history_visits.visit_time: When, in seconds since 1 January 2001 (UTC).
  • history_visits.title: The page's title at that visit.

Tables by iOS version

The same 9 tables in every backup we opened (iOS 13.3.1, 13.4.1, 15.3.1, 16.1.2 and 17.3):

history_client_versions, history_event_listeners, history_events, history_items, history_items_to_tags, history_tags, history_tombstones, history_visits, metadata

The iOS 16.0 backup is encrypted with a password that isn't public, so only its list of files was checked, not its tables.

How to open it

Free, in OpenExtract. Open the backup in OpenExtract and choose Web history. Timeline uses it too. OpenExtract lists every visit, newest first, with Firefox history alongside, and saves the list as CSV. Step by step: Export Safari history from an iPhone backup.

Always encrypted on disk. This file is only in encrypted backups, so the copy in the backup folder is encrypted with a key of its own, which only the backup password unlocks. Nothing can open it until it's decrypted. OpenExtract does that when you open the backup and type its password.
