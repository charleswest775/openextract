What it holds

Calendar.sqlitedb holds the Calendar app's events. Each event is a row in CalendarItem, with its title in summary and its times in start_date and end_date. Calendar lists the calendars, and Location the places events are at.

Key columns

  • CalendarItem.summary: The event's title.
  • CalendarItem.start_date: When it starts.
  • CalendarItem.end_date: When it ends.
  • CalendarItem.calendar_id: Which calendar it's in: its ROWID in Calendar.
  • Calendar.title: The calendar's name.

Then, version by version:

  • iOS 13.4.1 (37 tables): the same as iOS 13.3.1.
  • iOS 15.3.1 (38 tables): adds Conference.
  • iOS 16.1.2 (42 tables): adds AttachmentFile, AuxDatabase, AuxDatabaseAccount, Error.
  • iOS 17.3 (44 tables): adds AuxDatabaseChanges, Image.

The iOS 16.0 backup is encrypted with a password that isn't public, so only its list of files was checked, not its tables.

How to open it

OpenExtract doesn't read it yet. OpenExtract doesn't have a Calendar screen yet.

By hand. In a backup that isn't encrypted, 20/2041457d5fe04d39d0ab481178355df6781e6858 is an ordinary SQLite database with no extension. Copy it out of the backup folder and open the copy with any SQLite browser, such as DB Browser for SQLite. Work on a copy: changing anything inside a backup can stop it from restoring.

In an encrypted backup, the file in the backup folder is encrypted with a key of its own, which only the backup password unlocks, so nothing can open it until it's decrypted. Tools such as iphone_backup_decrypt, the open-source library OpenExtract uses, can decrypt a single file; then open the decrypted copy with any SQLite browser, such as DB Browser for SQLite.
